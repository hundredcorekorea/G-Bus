## 3. 1인기사/2인기사 구분, 보조기사 개념

### 실현 가능성: **중간 (2~3일)**

**현재**: `bus_sessions.driver_id`가 1명만 지원. 보조기사 개념 없음.

**변경 방안**:
- DB: `session_drivers` 중간 테이블 신설
  ```sql
  session_drivers (
    session_id, user_id, role: 'main' | 'sub',
    created_at
  )
  ```
- 세션 생성 시 "보조기사 초대" 기능 추가
- 초대용 계정도 보조기사로 등록 가능하도록 별도 `invite_code` 컬럼

**필요한 작업**:
- 마이그레이션 1개 (테이블 + RLS)
- `session/new` 페이지에 보조기사 선택 UI
- `session/[id]` 페이지에 보조기사 표시 + 권한 부여

### 난이도: 중간

## 9. 필드 사냥 소득 기록 / 메모 / 소득 그래프 / 평균 대비 %

### 실현 가능성: **중간 (3~5일)** — 새로운 기능 모듈

**현재**: 소득 관련 기능 없음. 완전 신규 개발.

**필요한 DB**:
```sql
field_income_logs (
  id UUID PRIMARY KEY,
  user_id UUID REFERENCES users,
  dungeon_name TEXT,
  earned_t BIGINT,           -- 수입 (T)
  memo TEXT,
  session_date DATE DEFAULT CURRENT_DATE,
  created_at TIMESTAMPTZ DEFAULT now()
)
```

**필요한 UI**:
- `/income` 페이지 신규
- 일별 수입 입력 폼 (던전 선택, 금액, 메모)
- 일별/주별/월별 그래프 (차트 라이브러리 필요: recharts 등)
- 전체 유저 평균 대비 자신의 소득 %
- 평균 계산: `avg(earned_t)` 집계 쿼리

**필요한 작업**:
- 마이그레이션 1개
- 차트 라이브러리 설치 (`recharts` 또는 `chart.js`)
- 소득 입력 페이지
- 그래프 대시보드
- 평균 대비 % 계산 RPC

### 난이도: **높음** (신규 모듈, 차트 포함)

## 기술적 제약 사항

1. **차트 기능 (9, 11, 12번)**: `recharts` 또는 `chart.js` 패키지 추가 필요. 현재 프로젝트에 차트 라이브러리 없음.
2. **보조기사 (3번)**: `bus_sessions` 스키마 변경 필요. 기존 `driver_id` 단일 컬럼 → 다대다 관계로 확장.
3. **소득 기록 (9번)**: 유저가 직접 입력하는 방식이라 UX 설계가 중요. 자동 추적은 게임 API 없이 불가능.
4. **Supabase 무료 플랜**: 500MB DB, 50K MAU 제한. 소득 로그/분석 데이터가 쌓이면 유료 전환 고려.
